    Plan: Boxbox 0.7.0 model routing

    Cheaper models do routine work through fixed-model subagents, every task gets a brief, a gate enforces the routing, and the pit wall and a status line show exact cost per model, with Codex unchanged apart from briefs.

    approved8 epics, 31 tasks

    Approved 2026-10-14. Building E1, starting with its design stop.

    Goal and non-goals

    Cheaper models do routine work through fixed-model subagents, every task gets a brief, a gate enforces the routing, and the pit wall and a status line show exact cost per model. Codex is unchanged apart from briefs. The work is eight epics on the branch model-routing, built one epic at a time with a stop for your review after each.

    Not in this plan

    • Live demo runs on a demo repo. You deferred them; the tests use fixtures trimmed from the real Step 0 transcripts instead.
    • Claude Code's own routing. None exists yet, and models: auto already steps aside if one ships.
    • An opusplan-style mode. Spike 8 found it exists but follows plan mode, not Boxbox stages.
    • A subagentStatusLine for subagent rows. A plugin can ship that one, but it is not needed for this release.
    • Codex prices in prices.json. Codex sessions keep showing their model per session with empty prices.

    The order, and why

    1. E1 first: the routing rule it defines is what every later epic checks against.
    2. E2 next: the briefs feed the gate's expected-diff and file checks.
    3. E3: the gate, which needs E1 and E2.
    4. E4: cost counting needs only E1, so it could run beside E2 and E3.
    5. E5: the pit wall views need the gate and the cost data.
    6. E6: the status line reads the cost data from E4.
    7. E7: parallel tasks need the briefs and the agent lanes.
    8. E8 last: the release checks everything that came before.

    Each epic builds on something already tested and reviewed, so a defect shows up at the epic that introduced it instead of surfacing in a later one that depended on it.

    Risks

    • highThe gate wrongly blocks real work

      A wrong denial would stop a subagent call you need. It is limited by judging only Boxbox agents, failing open on any internal error (D4), and standing aside under models: auto.

    • highShipping on tests alone leaves live-only behaviour unseen

      A live gate denial, a real parallel merge and the status line in a live session are first seen by users. This is your D5 override, and the README says so by marking those items "not yet verified in a live session".

    • mediumParallel worktrees start on the wrong base

      A builder could miss the epic's earlier tasks. Parallel mode is off by default and refuses to start without worktree.baseRef: "head" (D3).

    • mediumTokens are double counted or credited to the wrong task

      The fixture test checks per-model totals against a hand count of a session with three subagents (E4.3).

    • lowA future Claude Code changes how a subagent's model is resolved

      The gate compares the passed model to the expected one and never resolves a default, FORCE is detected, and auto steps aside.
