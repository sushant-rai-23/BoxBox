Boxbox 0.6 specimen

Jarvis on the pit wall

One system with two registers. The cockpit (pit wall and board) is dense and live. The manual (every page Boxbox writes) is calm long-form reading. Both share these tokens, families, spacing and status colours. The switch above controls this page; every frame below has its theme fixed so you can compare the two themes side by side.

Palette

Dark is pit-lane night: a petrol base, not near-black. Light is cool drafting paper, not cream. Neither theme is an inversion of the other: each status colour is tuned separately and passes 4.5:1 for text on both the page and raised surfaces (checked: lowest is 4.65 for live on light raised).

Grid

4 px base; spacing 4, 8, 12, 16, 24, 32, 48, 64, 96. Corners: 2 px on controls, none on blocks.

Cockpit: a 220 px rail, then a fluid deck with no max-width. One column under 1100 px, two from 1100 to 1700 px (Now and Needs you, Team radio below), three above 1700 px (Now, Needs you, Team radio side by side).

Manual: the prose column stays at 640 to 680 px (about 70 characters). From 1100 px a sticky contents column sits on the left and a margin column on the right for notes and file links. Code, diagrams and tables extend into the margin.

Principles

  1. Rules, not boxes. Type, alignment and a few strong rules make the hierarchy. A filled surface means code or "your move", nothing else.
  2. Colour is status. Six fixed colours, each with one meaning and always paired with a word. Everything else is ink.
  3. One bright centre. Rings, ticks and readouts live on the orb and the stage ruler only. The rest stays quiet.

Request path

ol.path. The steps in the order a request meets the code, each with span.at for file and line.

  1. The route receives the emailsrc/server.js:42

    Reads req.body.email and hands it on without checking whether it exists.

  2. Look up the usersrc/users.js:18

    findByEmail returns null for an unknown address. The path stops quietly here in that case.

  3. Create and store the tokensrc/resets.js:14

    32 random bytes, stored as a hash with a 30-minute expiry.

  4. Send the linksrc/mailer.js:61

    The raw token goes into the link and exists only in the email.

Decision

section.decision[data-state]: the question, why now, the comparison table, the recommendation, and a dl for the cost of changing it later and who decided.

answered

D2How long should a reset link stay valid?

E1 stores the expiry with every token, so this has to be settled before the first test is written.

OptionGainsCosts
30 minutesA forwarded or leaked email is useless quicklySlow mail servers can make a few links expire
24 hoursFewer "link expired" complaintsA day-long window for a leaked email

Recommendation: 30 minutes. It's the OWASP guidance, and the reset form can offer a new link when one expires.

Cost to change later
Low: one constant in src/resets.js.
Decided by
Priya, 11 October

Check yourself

ol.checks of details. Answers stay hidden until asked for.

  1. Why does an unknown email get the same 202 as a known one?
    If the answers differed, anyone could test which emails have accounts. The same answer every time gives nothing away.
  2. What happens if someone requests a reset twice?
    The second token replaces the first through upsert, so only the newest link works.
